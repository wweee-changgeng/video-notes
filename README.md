# video-notes

给 AI「看」视频的一套便宜办法：先用信号处理把结构抽出来，再让模型只读结构。

不是把视频一帧帧喂给模型，而是先切镜头、抓字幕、分章节，最后每章只送 3～4 张帧过去。

## 为什么这么做

直接抽帧塞给模型的毛病：

1. **贵**。一个三分半的片子几千帧，全送要好几十块。
2. **糊**。一次塞几十张，模型的注意力被摊薄，反而说不出细节。
3. **丢**。均匀抽帧遇到快速变化的画面会漏关键内容；长视频后半段经常直接「没了」。

换成先抽结构的做法：

| 步骤 | 干什么 | 成本 |
|---|---|---|
| 切镜头 | HSV 直方图找画面突变，分成镜头 | 本地，0 |
| 抓字幕 | 优先 OCR 画面里的硬字幕，没有才语音转写 | 本地，0 |
| 清洗 | 合并重复行、改同音错字 | 一次调用 |
| 切章 | 把带时间戳的台词交给模型，按话题切段 | 一次调用 |
| 描述 | 每章 3～4 帧 + 台词 → 画面里在发生什么 | 每章一次 |

参考成本：**187 秒的视频约 0.023 元**，其中 99% 花在最后的画面描述上。

## 安装

```bash
pip install -r requirements.txt
```

另外需要 **ffmpeg**（下载 B 站视频、抽音轨用）。Windows 上可以 `pip install imageio-ffmpeg` 然后 `python -c "import imageio_ffmpeg; print(imageio_ffmpeg.get_ffmpeg_exe())"` 拿到路径。

模型配置：复制 `config.example.json` 为 `config.json`，填上 `api_key`。也可以用环境变量 `DEEPSEEK_CONFIG` 指向别处的配置文件。

## 用法

```bash
# 本地文件
python run.py 视频.mp4

# B 站链接
python run.py "https://www.bilibili.com/video/BVxxxx/" --out out/demo

# 不做 OCR，直接语音转写
python run.py 视频.mp4 --no-ocr
```

跑完在输出目录里得到 `视频笔记.md`（每章：标题、时间、台词、画面描述、代表帧），帧图在 `shots/`。

## 几个关键参数

- **切镜头阈值不是固定的**。脚本会先测这条片子自己的直方图距离分布，取 p98 的 95%，再夹在 0.3～0.8 之间。讲解类 0.4 够用，第一人称游戏得抬到 0.8，硬套别人的参数会切出几百段。
- **`--min-gap`** 默认 2.5 秒，防止运动画面把一次移动切成几十段。
- **`--frames`** 每章送几张帧，默认 3。实测 4 张最准，8 张开始漏细节。

## 已知限制

这些不是没做，是现在做不到：

- **帧是抽的**。187 秒的片子 5610 帧，通常只看 27 张（0.5%）。中间的动作、表情变化根本不知道。
- **一次看不了一整段**。模型看到的是互不相连的静帧，没有时间维度，所以「这里情绪怎么变过去的」答不上来。真要连续得上视频模型，不是加帧能解决的。
- **BGM 全程垫着时测不出来**。人声/背景比要靠说话间隙做基线，说话占满全片就没有基线。
- **歌词和台词分不开**。两者都是人声，除非有硬字幕做锚点。
- **平台绑定**。硬字幕 OCR 用的是 Windows 自带的 OCR 引擎，Linux/macOS 上要换。

## 文件

```
run.py                  入口：一条命令跑完
layer1_shot_split.py    镜头切分 + 中点帧导出
ocr_subtitles.py        画面底部硬字幕 OCR（变化检测后才识别）
transcribe_segments.py  语音转写，带词级时间戳
polish_subs.py          字幕去重 + 错字校正
split_semantic.py       按话题切章
describe_chapters.py    每章帧 → 画面描述
assemble_note.py        拼成带图的 Markdown 笔记
audio_align.py          人声/背景比、切点与鼓点对齐
music_v2.py             纯音乐：鼓点 → 调性 → 和弦
```
